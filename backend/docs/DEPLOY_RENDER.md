# Deploying PocketLab on Render

`render.yaml` at the repository root is a Render Blueprint that creates:

| Resource | Name | URL |
|---|---|---|
| PostgreSQL (free) | `pocketlab-kkb-db` | internal |
| API (Docker, free) | `pocketlab-kkb-api` | `https://pocketlab-kkb-api.onrender.com` (docs at `/docs`) |
| Dashboard (static) | `pocketlab-kkb-web` | `https://pocketlab-kkb-web.onrender.com` |

## Deploy

1. Open <https://render.com/deploy?repo=https://github.com/kartikkumarbadgujar/pocketlab> and sign in (GitHub login works).
2. Grant Render access to the repository if asked, review the three resources, and click **Apply**.
3. Wait for the API (Docker build, about 3–5 minutes) and the dashboard (npm build) to go live.

On every start the API runs `alembic upgrade head` and the idempotent catalog seed. `JWT_SECRET` and `RUNNER_TOKEN`
are generated by Render; copy `RUNNER_TOKEN` from the API service's *Environment* tab when you connect a worker.

**If Render gives a service a different URL** (it appends a suffix when a name is taken): if the API's URL differs,
set `VITE_API_BASE_URL` on `pocketlab-kkb-web` to `https://<actual-api-host>/api/v1` and redeploy the dashboard. A
suffixed dashboard URL needs no change; `CORS_ORIGIN_REGEX` already allows it.

## Running Android tests against the hosted API

The Android worker cannot run on Render (no Android SDK or hardware virtualization). Run it on a laptop or VM:

```powershell
$env:POCKETLAB_API_URL = "https://pocketlab-kkb-api.onrender.com/api/v1"
$env:RUNNER_TOKEN = "<RUNNER_TOKEN from Render>"
python -m app.workers.emulator_runner
```

Approve an uploaded build from your machine using the database's **External Database URL** (Render → database →
Connect). The APK lives on the API's disk, so approval uses the database record; the worker re-checks the SHA-256:

```powershell
$env:DATABASE_URL = "<External Database URL>"
python -m scripts.approve_build <build_id> --remote-storage --reason "Team-owned demo build"
```

## Free-tier limits that matter for a demo

* **Uploads are not persistent.** The free API instance has no persistent disk, so uploaded APKs and evidence files
  disappear when the instance restarts or redeploys. Upload, approve and run in one session, or upgrade the API to a
  paid plan and add a disk mounted at `/app/private_uploads`.
* **Sleep after ~15 minutes idle.** The first request after that takes up to a minute (and, per the point above,
  restarts clear uploads).
* **The free PostgreSQL database expires after 30 days.**
* The per-process rate limiter (120 requests/minute per client IP) is fine for a single free instance.
